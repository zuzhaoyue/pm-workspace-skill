# pm-workspace

**给产品经理的本地知识库脚手架。** 一句话装好,然后通过对话把脑子里的业务口径搭成 AI 每次都会先读的上下文。

## 这是在解决什么问题

产品经理的业务知识散在飞书文档、微信聊天、和脑子里。于是:

- 同一条口径,今天问 AI 和明天问 AI,答案不一样;
- **把「还在聊的方案」当成「线上已有的功能」**去答客户、去排开发 —— 这个错最贵;
- PRD 改了知识库没改,下次又按旧口径写。

本项目让你在本地搭一个知识库,AI 每次工作前先读它,**答出来的东西有唯一权威口径**。

核心是一条很笨但很管用的规则:**业务上下文按上线状态分三个文件夹**。

```
业务上下文/
├── 已上线业务/      线上现在的实际行为,能直接答客户
├── 已确认需求/      规格已锁定、等排期,能排开发 —— 但不是线上现状
└── 沟通中需求/      还在聊,口径会变,引用前先看待确认清单
```

状态不写在文件里,写在**文件夹**上。功能上线了,整套文件换文件夹。
这样 AI 读到任何一条规则,都先知道它算不算数。

## 怎么装

把下面这段话发给你的 AI,就完成了安装:

> 请阅读 https://raw.githubusercontent.com/zuzhaoyue/pm-workspace/main/SKILL.md
> 并按照文件里的「安装」一节完成安装,安装完成后告诉我你能做什么

目前只在 **Claude Code** 上验证过,复制粘贴发送即可,装完**重开一次会话**生效。

其他 AI Agent(Cursor 等)理论上也能用 —— 把 SKILL.md 的内容原样放进它的规则文件就行,
一个字都不用改 —— 但**我没实测过**,触发方式和效果都不保证。

## 怎么用

新建一个**空文件夹**,在里面开 AI,说任意一句:

- `/workspace-init`
- 「帮我搭个产品经理的工作台」
- 「给 XX 产品建个知识库」

然后它会**一次只问一个问题**,一共 6 题,答不上来的可以跳过:

1. 产品叫什么?一句话是干嘛的?给谁用?
2. 怎么赚钱?怎么计费?
3. 有哪些端、分别给谁用?
4. 内部文档写什么语言?产品界面文案是什么语言?
5. **现在手上的功能,分别在哪个阶段?**(已上线 / 定了没上线 / 还在聊)
6. 你日常要交付什么?

答完就生成好了。产出长这样:

```
你的产品/
├── CLAUDE.md                     AI 每次工作前必读:协作方式 + 知识维护规则 + 当前状态
├── 业务上下文/
│   ├── 00-产品概览.md             产品是什么、端划分、功能索引
│   ├── 已上线业务/
│   ├── 已确认需求/
│   └── 沟通中需求/
├── prd/
└── 原型/
```

一个完整的生成样例见 [例子/健身房会员系统/](例子/健身房会员系统/)。

## 它替你守住的几条规矩

装完之后,AI 在这个文件夹里干活会遵守:

| 规矩 | 为什么 |
|---|---|
| 一次只问一个问题 | 一口气抛十个问题,人只会挑着答,剩下的全靠猜 |
| 不得基于猜测撰写,没说的留 `(待填)` | 编出来的规则读起来最顺,也最容易被当真 |
| 未定口径标 **【待确认】** 并配通俗事例 | 「金额为负时怎么处理」两周后没人看得懂在问什么 |
| 待确认编号 = 组字母+序号,删除时后面的**不重编号** | 编号一错位,历史文档里的引用就全废了 |
| 业务规则文件是权威口径,不得默默推翻 | |
| 规则改了 → 必须回头同步 PRD | 知识库和 PRD 对不上,是这套东西最常见的死法 |
| 功能状态变了 → **整套文件换文件夹** | 别只改文字不挪文件 |

## 装完之后最该做的一件事

把「还在聊」的那些功能,**未定的口径逐条记进待确认清单,每条配一个通俗事例**。

这一步最费劲,也最值钱 —— 它是把「我心里大概有数」变成「团队有唯一答案」的唯一途径。

## 它不做什么

- 不生成日报/周报,不生成 Word 导出工具链 —— 只搭知识库骨架和维护规则;
- 不替你做需求判断 —— 它只保证你做过的判断不会被记错、记丢、记乱。
