# pm-workspace-skill

**给产品经理的本地知识库脚手架。** 一句话装好,然后通过对话把脑子里的业务口径搭成 AI 每次都会先读的上下文。

## 这是在解决什么问题

产品经理的业务知识散在飞书文档、微信聊天、和脑子里。于是:

- 同一条口径,今天问 AI 和明天问 AI,答案不一样;
- **把「还在聊的方案」当成「线上已有的功能」**去答客户、去排开发 —— 这个错最贵;
- PRD 改了知识库没改,下次又按旧口径写。

本项目让你在本地搭一个知识库,AI 每次工作前先读它,**答出来的东西有唯一权威口径**。

核心是一条很笨但很管用的规则:**业务上下文按上线状态分三个文件夹**。

```
业务上下文/
├── 已上线业务/      线上现在的实际行为,能直接答客户
├── 已确认需求/      规格已锁定、等排期,能排开发 —— 但不是线上现状
└── 沟通中需求/      还在聊,口径会变,引用前先看待确认清单
```

状态不写在文件里,写在**文件夹**上。功能上线了,整套文件换文件夹。
这样 AI 读到任何一条规则,都先知道它算不算数。

## 怎么装

### 第 0 步:先有 Claude Code(一次性,以后不用再做)

⚠️ **Claude Code 需要 Pro / Max / Team / Enterprise 付费订阅**,免费版用不了。

**不用碰终端、不用装 Node.js**,下载桌面 App 就行:

- [macOS 下载](https://claude.ai/api/desktop/darwin/universal/dmg/latest/redirect)
- [Windows 下载](https://claude.ai/api/desktop/win32/x64/setup/latest/redirect)

装完打开,用你的 Anthropic 账号登录。

### 第 1 步:装这个 skill

1. 打开 Claude App,**切换到 Code 模式**。
   ⚠️ **必须是 Code,不能是 Chat** —— Chat 没有读写文件的权限,口令发进去 AI 会回你
   「已读完」,但其实什么都没装上。
   不同版本位置不一样:可能是顶部中间的 **Code** 标签,也可能是左上角的 **`</>`** 图标
   (旁边那个对话气泡就是 Chat)。选中的那个会高亮。
   如果点了提示要升级,是订阅问题,见第 0 步。
2. **选一个本地文件夹**。输入框正上方有一行按钮:`Local`(在你自己电脑上跑,别动)、
   当前文件夹名、以及一个**文件夹＋**图标。点那个图标会弹出系统文件选择器,随便选一个
   文件夹就行。
   > 这一步选哪个文件夹**都无所谓** —— skill 装到你的用户目录,跟选的文件夹无关。
   > 已经有文件夹开着的话直接用,不用另外新建。
3. 在下方输入框里粘贴这段话,回车:

   > 请阅读 https://raw.githubusercontent.com/zuzhaoyue/pm-workspace-skill/main/SKILL.md
   > 并按照文件里的「安装」一节完成安装,安装完成后告诉我你能做什么

4. Claude 会下载文件、写到你的用户目录,然后告诉你它能做什么。中途可能弹窗问
   「是否允许执行这条命令」,点允许。
5. **关掉当前会话、重新开一个**(侧边栏 **New**),skill 才会生效。

## 怎么用

**这一步必须新建一个真正的空文件夹**,用来装这个产品的知识库,名字建议就用产品名。
(和上一步随便选的那个不是一回事 —— 装 skill 不挑文件夹,搭工作区必须是干净的空文件夹。)

在 Claude App 里按上面第 2 步的办法把它选中,然后说任意一句:

- `/workspace-init`
- 「帮我搭个产品经理的工作台」
- 「给 XX 产品建个知识库」

它会**先问你有没有现成的文档** —— PRD、需求文档、竞品调研、会议纪要、
飞书/Notion 导出的 md 都行,**拖进对话框**或者复制进那个文件夹就能给它。
有文档的话它先读一遍,后面的问题就变成跟你核对,快得多;没有也完全不影响。

> ⚠️ 但**上线状态它一定会问你,不会从文档里推** —— 一份 PRD 躺在那儿,
> 不代表那个功能上线了,可能早就废弃、也可能还在排期。这是整套方法的地基,
> 推错了后面全错。

然后**一次只问一个问题**,只有 3 题,答不上来的可以跳过:

| # | 问题 | 答起来长这样(以钉钉举例) |
|---|---|---|
| 1 | 你的产品是什么?给谁用?怎么赚钱? | 钉钉,企业办公协同平台,给中小企业的 HR 和行政用;基础版免费,专业版按人数收年费 |
| 2 | 有哪些端?分别谁在用? | 员工手机 App + 管理后台(HR 用)+ PC 客户端 |
| 3 | **手上的功能分别在哪个阶段?** | 考勤打卡=已上线;审批流自定义=定了等排期;AI 会议纪要=还在聊 |

**第 3 题是关键** —— 它决定了每个功能被放进哪个文件夹,也就决定了以后 AI 会不会
把「还在聊的」当成「已经有的」。

文档语言、要交付什么这两件事**不问**,直接给默认值(同语言、建 `prd/` 和 `原型/`),
最后验收时你一句话就能纠正 —— 逼人答 6 题不如给个默认让他否认。

答完它**不会把你的话复述一遍**再问下一题,只在最后统一确认一次。

答完就生成好了。产出长这样:

```
你的产品/
├── CLAUDE.md                     AI 每次工作前必读:协作方式 + 知识维护规则 + 当前状态
├── 业务上下文/
│   ├── 00-产品概览.md             产品是什么、端划分、功能索引
│   ├── 已上线业务/
│   ├── 已确认需求/
│   └── 沟通中需求/
├── prd/
└── 原型/
```

照这六个答案跑出来的完整样例见 [例子/钉钉-示例/](例子/钉钉-示例/)。
(注意里面大量 `(待填)` —— 用户没讲过的,它一个字都不编。)

## 它替你守住的几条规矩

装完之后,AI 在这个文件夹里干活会遵守:

| 规矩 | 为什么 |
|---|---|
| 一次只问一个问题 | 一口气抛十个问题,人只会挑着答,剩下的全靠猜 |
| 不得基于猜测撰写,没说的留 `(待填)` | 编出来的规则读起来最顺,也最容易被当真 |
| 未定口径标 **【待确认】** 并配通俗事例 | 「金额为负时怎么处理」两周后没人看得懂在问什么 |
| 待确认编号 = 组字母+序号,删除时后面的**不重编号** | 编号一错位,历史文档里的引用就全废了 |
| 业务规则文件是权威口径,不得默默推翻 | |
| 规则改了 → 必须回头同步 PRD | 知识库和 PRD 对不上,是这套东西最常见的死法 |
| 功能状态变了 → **整套文件换文件夹** | 别只改文字不挪文件 |

## 装完之后最该做的一件事

把「还在聊」的那些功能,**未定的口径逐条记进待确认清单,每条配一个通俗事例**。

这一步最费劲,也最值钱 —— 它是把「我心里大概有数」变成「团队有唯一答案」的唯一途径。

## 它不做什么

- 不生成日报/周报,不生成 Word 导出工具链 —— 只搭知识库骨架和维护规则;
- 不替你做需求判断 —— 它只保证你做过的判断不会被记错、记丢、记乱。
