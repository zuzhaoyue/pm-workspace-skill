# 竞品分析

## 这个 skill 在防什么

竞品分析最常见的死法有三种,而且都看不出来:

1. **做成了大而全的功能对比表** —— 三十行打勾打叉,看完不知道自己该做什么。
2. **证据是推测的** —— 「他们应该是这么做的」写着写着就变成了「他们是这么做的」。
   最隐蔽的一种:自己照着印象**画了张示意图**,读者当成了对方的真实界面。
3. **结论落不了地** —— 「值得借鉴」「可以参考」,然后就没有然后了。

下面每一节都是在堵这三个洞。

## 1. 开工前先定三件事(不定就别开始)

**① 这次调研要回答什么决策?** 一句话写下来,写不出来就先别做。

- ✅「我们的通知中心,未读数字该按『读没读』算还是按『事做没做』算?」
- ❌「调研一下竞品的通知功能」—— 这不是决策,是开放式闲逛,做完必然是大杂烩。

**② 找谁比?** 三类,按需要挑,别贪多:

| 类型 | 举例 | 看什么 |
|---|---|---|
| **直接竞品** | 同赛道同客户 | 客户拿来和你对比的就是他们,差异要能解释 |
| **同形态的大厂** | 功能形态像,赛道不同 | 交互惯例。用户在别处养成的习惯会带到你这儿 |
| **做得最狠的那家** | 把这个功能做到极致的 | 看上限在哪,以及代价是什么 |

**3~5 家就够了。** 十家的调研不会比五家更有说服力,只会更没人看完。

**③ 比什么维度?** 从 ① 的决策**倒推**,不要套通用模板。
要回答「未读数字怎么算」,维度就是「怎么算未读」「点开算不算已读」「有没有全部已读」——
而不是「界面美观度」「操作便捷性」这种打分项。

## 2. 证据规则(这节最要紧)

**只有三种算一手证据:**

- 官方文档 / 帮助中心 / 更新日志
- **真机实测截图**(自己注册个账号点一遍)
- 官方公开的产品演示

**每条证据都要标:来源 URL + 获取日期。** 产品会改版,没有日期的截图三个月后就成了谣言。

### ⚠️ 三条红线

1. **不要自己画示意图来表示竞品界面。** 哪怕标了「示意」,读者的记忆里也会存成「对方长这样」。
   要么放真实截图,要么用文字描述并说明「未获取到截图」。
2. **截图要存进仓库**,不要只贴链接。对方改版 / 删页面之后,链接就成了死证据。
   建议放 `参考资料/竞品截图/<功能名>/`。
3. **查不到就写「未查到」。** 不要用「推测应该是」填空 —— 一旦写进文档,
   下一个读的人就会当成事实引用。

### 证据分级标注

正文里每条结论后面挂一个来源标记,让读者自己判断可信度:

- `[实测]` —— 自己点过,截图在库
- `[官方文档]` —— 有链接
- `[二手]` —— 来自测评文章 / 他人转述,**可信度低,只作方向推导**

**二手证据不能单独支撑结论。** 一条结论只有二手来源 → 要么去实测,要么降级成「待验证」。

## 3. 怎么写

### 3.1 结构

```
# <功能名> 竞品调研

## 0. 这次要回答什么
   <第 1 步 ① 的那句话,原样放这里>

## 1. 调研对象与理由
   | 产品 | 为什么选它 | 证据等级 | 获取日期 |

## 2. 逐家看
   ### 2.1 <产品 A>
   <按第 1 步 ③ 定的维度逐条写,每条挂来源标记>
   <截图放这里,配一句说明「这张图说明了什么」>

## 3. 横向对比
   <只对比第 1 步 ③ 定的那几个维度。别加「综合评分」>

## 4. 结论与取舍
   <见 3.2>

## 5. 未查到 / 存疑
   <老老实实列出来。这一节空着反而可疑>
```

### 3.2 结论怎么写才落得了地

每条结论**必须能接上「所以我们…」**:

- ✅「五家里有四家把未读按『读没读』算,只有 X 家按『事做没做』。
  后者要维护完成态,判定不可靠。**所以我们按『读没读』算。**」
- ❌「各家做法不一,值得进一步研究。」

**结论之间有冲突时,写清取舍,不要和稀泉。**
「A 家的做法体验更好但要多做一套后台;我们一期人力不够,**先按 B 家的简化版做,
二期再补**」—— 这种句子才是调研的价值所在。

### 3.3 不要写的东西

- 综合评分、雷达图、五星打分 —— 分是自己给的,改个权重结论就反了
- 「界面美观」「体验流畅」这类无法证伪的形容
- 对方的商业数据(融资额、用户数)—— 除非这次决策真的跟它有关
- 长篇的产品背景介绍 —— 读者要的是差异,不是百科

## 4. 调研完之后(别让它变成一次性文档)

1. **结论落进业务规则**:被采纳的做法,写进 `<功能>-业务规则.md`,**并注明「据竞品调研,见 §X」**。
2. **取舍落进决策记录**:为什么没选另一种,写进 `<功能>-决策记录.md` ——
   防止三个月后有人重提已经否决过的方案。
3. **调研文件本身**留在该功能所在的文件夹(`沟通中需求/` 或 `已确认需求/`),
   命名 `<功能名>-竞品调研.md`。
4. ⚠ **调研文件不是权威口径**。它是**当时**的观察,产品会改版。
   业务规则文件才是权威 —— 调研只是它的论据来源之一。

## 5. 重做一版时

竞品改版、或者当初用的是二手证据,需要重做:

- **新旧两版并存**,新的叫 `-竞品调研v2.md`,旧的留着。
- 在**新版顶部**写明:相比 v1 改了什么、为什么重做(例:「v1 用的是我方重绘示意图,
  可信度存疑;v2 全部换成实机截图」)。
- 在**旧版顶部**加一行:「⚠ 已由 v2 取代,只作方向推导」。
- **不要直接覆盖** —— 当初基于 v1 做的决策,得能追溯到它依据的是什么。
